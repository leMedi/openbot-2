# Grok Bot: UI and UX teardown

This is the UI spec for rebuilding Grok Bot's desktop renderer as our own web app (TanStack Start + React + Tailwind + shadcn/ui). It describes structure, behaviour, copy and design tokens. It does not reuse code or brand assets: the icon font, the persona character artwork, the wallpaper and the Grok/Cursor names stay out of openbot.

Paths are relative to `frontend/src/` in the reconstruction unless noted. Most features live under `recovered/features/`, so `conversation/workspace/sidebar.tsx` means `recovered/features/conversation/workspace/sidebar.tsx`. The root composition is `production/ProductionRenderer.tsx` (one 3,700-line component). Claims are marked **[inferred]** when deduced rather than read in code.

---

## 0. Reading notes and caveats

- **Atomic class names.** The shipped renderer uses StyleX, so markup carries hashed atoms such as `sand-78zum5` (`display:flex`). They resolve to declarations in the generated sheet `computer/shell/view.css` (64 KB, minified). The values quoted in this doc come from resolving those atoms.
- **Theme tokens** are generated at runtime by `runtime-theme-token-installer.ts`, which writes a `<style id="sand-cursor-theme">` with about 400 CSS variables per mode. Two layers matter: `--sand-*` (the design system) and `--cursor-*` (aliases inherited from the Cursor IDE theme). Section 7 lists the effective values.
- **Reconstruction artifacts to ignore:**
  - A few transcript rules in `conversation/workspace/view.css` hard-code a greenish dark palette: `#20231f` surfaces, `#a9c85d` focus rings, `#bfe86b` / `#c7ec6b` links and accents. These are used for hover actions, code blocks, the typing indicator, the media viewer and the unread divider. They contradict the token system, and are almost certainly reconstruction placeholders **[inferred]**, so use tokens instead.
  - The settings and plugins dialogs fall back to `Inter` and hard-coded dark hex values. Use the system font and tokens.
  - The settings **Router** section (Cursor / Claude Code / Codex / OpenRouter) exists only in the reconstruction.
  - `dev/DevShell.tsx` is a reconstruction harness with a DOM inspector and fixture previews, not product UI.
  - In the reconstruction, right-hand panes render as siblings of the 2-column grid. The shipped pane carries `grid-column:3; grid-row:1`, so the real shell is a 3-column grid **[inferred]**.
- **Broadcast is dead UI.** `production/evidence.ts` records that the shipped build has "no current user path" for it, and the org chart is behind an experiment flag.

## 2. Sidebar / roster

Code: `conversation/workspace/sidebar.tsx`, `sidebar-agent-status.ts`, `sidebar-agent-preview-*.tsx`, `production/AgentRowActions.tsx`, `production/agent-row-actions-model.ts`, `sidebar-section-*.ts(x)`.

### 2.1 Structure (top to bottom)

1. **Header**, 50px, padding `0 12px 0 16px`, with a hairline bottom border. Its only live control is the **New** icon button (`+`, 24px). Hidden behind flags: Broadcast (megaphone) and Agent network (org chart).
2. **Search**: a secondary 28px button, "Search", with a 0.5px inset ring. It opens the command palette (`⌘⇧F` also works).
3. **List** (`nav.sand-agents-list`): padding `4px 12px 24px`, row gap 3px, scrolls.
   - **Pinned group** comes first, in a user-defined order that can be dragged to reorder (drop on the top or bottom half of a row).
   - **Sections** follow. They are user-named folders, plus a synthetic **"Unassigned"** section (`__agents__`) that holds the rest and is hidden when empty.
   - With no sections defined, the list is flat.
4. **Footer** (`padding: 2px 12px 12px`):
   - "Hidden Bots" secondary button with a count badge, shown only if some Bots are hidden.
   - **Plugins** pill (plug icon, 38px tall, 10px radius).
   - The update pill, when an update is ready.
   - **Account button**: 40px tall, 30px avatar tile (accent fill with the initial, or a photo), name 13px/600, email 11px secondary.

### 2.2 Agent row

| Part | Spec |

**Status model** (`sidebar-agent-status.ts`):

| State | Condition | Expanded row | Pinned / compact row |
|---|---|---|---|
| Working | running and not waiting | green dot on the avatar corner | corner dot |

Dot colours: working `--sand-fill-success`, attention `--sand-fill-warning`, unread/info `--sand-fill-accent`, offline `--sand-fill-neutral`, error `--sand-fill-danger`. Dots appear with a 130ms pop on `cubic-bezier(.22,1,.36,1)`.

**Hover card**: hovering or focusing a row shows a popover with a small avatar, name, title tag, pinned marker, "5m ago", and the preview or "No messages yet". The preview is the full waiting reason or `Draft:` when those apply (`sidebar-agent-preview-content.tsx`).

### 2.3 Context menu and multi-select

Right-click (or the Context-menu key / Shift-F10) opens "Agent actions". Order, from `AgentRowActions.tsx` and `agent-row-actions-model.ts`:

1. Edit Profile (1:1 only) → opens the agent settings pane
2. Show full conversation → outline panel (§3.9)
3. Show async tasks (internal users only)
4. Move to ▸ (submenu listing the sections + "New section"), or "Move to new section" if there are no sections. Not offered for pinned rows.
5. Pin / Unpin
6. Mark as Read / Mark as Unread
7. Duplicate (1:1 only)
8. Copy conversation ID
9. Hide from sidebar
10. Delete → confirmation dialog

Rows can be dragged into a section; the drop target gets an accent-subtle fill and a focus outline. `⌘/Ctrl-click` toggles selection and `Shift-click` range-selects. With a selection, the header is replaced by **Move ▾ / Delete (danger) / Clear**.

**Sections**: the header is 30px, padding `8px 8px 6px`, 6px radius, secondary text. Clicking it folds the section; a folded header shows the count, and a chevron appears on hover. Its context menu offers Rename / Move up / Move down / Delete. Deleting asks "Delete “X”", and the agents move to Unassigned. An empty section body reads "Drag chats here". Creating a section from "Move to new section" drops straight into rename.

### 2.4 New Bot / new group flows

- **New** (`⌘N`) immediately creates an agent named "New chat" with an empty description and opens it. There is no dialog: the user names the Bot by chatting, or the Bot renames itself (a "name-changed" timeline event appears).
- **No user-facing "New group" UI exists** in the renderer. Groups are created through the API (`createGroup`), in practice by Bots or flows outside the roster **[inferred]**. Membership is then edited in the Group members pane (max **6** members).
- Hidden Bots: a modal lists them with **Unhide**, and its copy says "Hidden Bots stay active and keep their history, they just don't show in the sidebar." If every Bot is hidden, the list shows "All bots are hidden" with **Show Hidden Bots**.
- Roster states (`roster/status.tsx`): "Connecting to your computer…", "No saved agents yet.", "Can’t reach your computer — Your agents are safe…" with Retry, and the reconnect notice "Reconnecting to your computer…".

### 3.6 Agent-to-agent entries

The host writes bot-to-bot traffic into each Bot's own 1:1 transcript (`source/host/extensions/transcript/agent-to-agent-messaging.ts`):

- **Inbound**: `role:"user"` with `fromAgent:{id,name}`, appearing on the user side of the recipient's chat.
- **Outbound**: `role:"assistant"` with `toAgent`, appearing on the sender's side.
- **No unread**: neither entry raises activity. `entryRaisesUserActivitySignal` (`shared/transcript.ts:41`) is false for any message with `fromAgent` or `toAgent`, and only it calls `markSessionActivity`, which bumps the unread count.
- **Images**: `SendToAgent` takes `images: [{url, alt?}]`, `file://` or `https://` (`runner/tools/sand-agent-management-tools.ts:38`). A 1:1 recipient gets them as `selectedImages`, image input to its run, but `loadAgentInboundImages` keeps only `file:` URLs and `resolveImageSource` is never wired in (`host-runner-composition.ts:1995`), so an `https://` image shows in the chat yet never reaches the recipient's model. A group post is text only: the images are dropped and the tool result says "NOT delivered".

The renderer treats these as a "special-variant" message card whose visuals were not recovered (`conversation/message-card-seam.ts`). **[inferred]** They render as bubbles with a small "from X" / "to X" attribution, so you can tell them from your own messages. In groups, every member's message is an agent bubble, and the author is shown at the start of each author group **[inferred]**, since grouping keys on `role:author`.

### 3.7 Typing and working indicators

- While the active Bot runs, a **typing indicator** (three 5px dots in a 14px-radius pill, padding `10px 12px`) sits at the end of the transcript.
- The header shows "Working". The sidebar row shows the green dot and the activity line, and the avatar animates.

### 8.4 Behaviours worth copying exactly

1. Multi-bubble agent replies with tight grouping and the pop-in animation. Hide all tool and reasoning output from the main chat.
2. Status everywhere at a glance: avatar corner dot (working), trailing dot (needs you / unread), `Waiting for you: …` and `Draft: …` previews.
3. Letter-key answers on question widgets, and save-on-blur forms with no Save buttons.
4. One right-hand pane at a time, resizable, with the computer preview as its default.
5. Take-over flow in three places (transcript card, pane attention card, fullscreen banner), always offering **Skip** and **I'm done, continue**.
6. Monochrome primary buttons with blue reserved for links, focus and unread, and no shadows in dark mode.
