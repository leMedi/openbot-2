# Working in Linear

- Search for an existing issue before filing a new one; comment on it instead of duplicating it.
- File issues in the right team, with a short title that says what is wrong or wanted, and a description with steps, expected and actual results when it is a bug.
- Set the fields the team uses (priority, labels, project, cycle) when you know them; don't guess an assignee.
- Move an issue's status only when the work has actually changed state, and say why in a comment.
- Give the issue's identifier and link (e.g. ENG-123) in your answer.
